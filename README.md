# 더그아웃 0.3

웹에서 플레이: https://jinuk-e.github.io/BaseBallLife/

`main`에 변경 사항을 올리면 GitHub Actions가 규칙 테스트 후 `dist/`를 GitHub Pages로 배포한다. 웹 저장은 브라우저마다 별도로 보관되며, 로컬 게임의 저장은 파일 내보내기·가져오기로 옮길 수 있다.

고교의 첫 유니폼부터 40세 마지막 시즌까지 이어가는 로컬 야구 선수 커리어 게임이다. 타자 또는 선발·중계·마무리 투수로 훈련, 몸 관리, 포지션, 계약을 선택한다.

## 실행과 공유

집에서 개발을 이어갈 때는 Node.js 22 이상과 Git을 설치하고 다음을 실행한다. 외부 npm 패키지를 설치할 필요는 없다.

```sh
git clone https://github.com/JinUk-E/BaseBallLife.git
cd BaseBallLife
npm run build
npm start
```

브라우저에서 `http://127.0.0.1:4173`을 연다. 서버 없이 플레이하려면 빌드로 생성된 `play.html`을 연다. 검증은 `npm test`로 실행한다.

저장소에는 수정 가능한 `dist/` 원본을 보관한다. 생성 파일 `play.html`과 배포용 ZIP, 로컬 브라우저 프로필은 Git에 넣지 않는다. 설계·작업 맥락은 [기획 문서](docs/planning/README.md), 다음 개발 제안은 [개발 인수인계](HANDOFF.md)를 참고한다.

**`play.html`을 Chrome 또는 Edge로 열면 바로 실행된다.** `게임시작.cmd`도 같은 파일을 연다. 설치·서버·인터넷 연결이 필요 없다. 공유할 때는 `play.html` 하나만 압축해도 된다. 웹 버전은 위 GitHub Pages 주소에서 플레이할 수 있다.

기존 파일을 같은 위치에서 갱신하면 그 브라우저의 저장을 이어갈 수 있다. 파일 경로·브라우저가 달라지는 경우에는 게임 설정에서 저장 파일을 내보내고 새 파일에서 가져온다. 자동 저장은 각자의 기기에 남는다.

## 플레이 흐름

- **고교 시작:** 16세로 가상 학교에 입학한다. 주말 중심 28경기를 세 시즌 치르고, 성적·능력을 반영한 KBO 지명 구단에 19세로 입단한다. 고교 성적은 프로 통산과 분리한다.
- **프로 바로 시작:** 19세부터 한국·일본·미국 중 선택한 구단의 신인으로 시작한다.
- **나이와 성장:** 생성 때 정한 능력별 상한·성장 속도·회복력은 유지된다. 10대와 20대 초반에는 빠르게, 이후에는 완만하게 성장한다. 30세부터 훈련은 유지에 집중하고 잠재력·회복력·부상 이력에 따라 능력이 유지되거나 서서히 감소한다.
- **부상 완화:** 부상 발생 시 관련 능력 최대 2개만 소폭 감소한다. 한 시즌의 부상 손실은 전 능력 합계 2 이내다. 부상 기간의 반복 영구 차감은 없고 피로 자체도 능력을 영구 차감하지 않는다.
- **아이템:** 회복 키트·성장 훈련권·보호 장비를 무료 게임 포인트로 구매·사용한다. 성장 훈련권은 30세 이후에는 노화 감소를 돕는다.
- **계약:** FA 전에는 소속팀의 보류권 아래 연봉을 갱신한다. 자격 취득 후 1~4년 계약을 선택하며 계약 중에는 소속팀과 연봉을 유지한다. FA 행사를 유보하고 같은 팀에 1년 잔류할 수도 있다.
- **정규시즌 일정:** 주간 진행 화면에 날짜와 상대 팀이 표시된다. 일정·순위에서 월별 홈/원정 대진을 볼 수 있다. 휴식 주에도 훈련과 회복은 가능하다.

## 이전 저장

v1/v2 저장은 검증 후 기록과 나이를 보존해 전환한다. 진행 중인 기존 시즌은 16주·112경기를 유지하며 다음 시즌부터 새 일정과 계약 구조를 적용한다. 이미 은퇴한 저장은 은퇴 상태를 유지한다. v1·v2 원본은 각각 별도 보관하고 설정에서 내보낼 수 있다. 저장 파일 가져오기와 새 선수 시작은 현재 선수의 저장을 교체한다.

## 개발·검증

최종 규칙 시험 42개를 통과했다. 24명의 19~40세 프로 전 경력 528시즌과 고교부터의 전 경력, 부상 손실 상한, FA·유보·다년 계약, 리그별 실제 경기 수, 선발 최소 5일 간격, 저장 전환을 검증했다. Edge 실제 화면에서 고교→프로·계약·일정·저장 가져오기를 확인했으며 브라우저 오류 0건, 모바일 360px 가로 넘침 0건이었다.

40개 과로 시즌에서 부상 영구 손실은 전 능력 합계 평균 0.897, 최대 2.0이었다. 균형 훈련·피로 60 초과 시 회복하는 20개 시드 표본의 첫해 평균 능력 증가는 고교 +9.34, 19세 프로 +5.15였다. 플레이 선택과 잠재력에 따라 결과는 달라진다.

- 단일 실행 파일 생성: `node export-standalone.cjs`
- 규칙 테스트: `node --test tests/*.test.cjs`
- 개발 서버: `node server.cjs` → `http://127.0.0.1:4173` (이 컴퓨터에서만 접근)
- 성장 비교 재현: `node scripts/balance.mjs`

`dist/core.js`는 게임 규칙, `league-data.js`는 구단·학교, `schedule-data.js`는 공식 일정과 개발 계획, `legacy-core.js`·`legacy-v2-core.js`는 이전 저장 검증, `app.js`는 화면·입력·저장, `styles.css`는 화면 구성을 담당한다. 외부 패키지나 원격 자산 없이 게임을 실행한다.

## 빠른 진행과 전설 목표 업데이트

- 기본 진행은 4주이며, 1주 또는 다음 주요 선택까지 진행할 수도 있다. 빠른 진행에서는 피로 60 이상이나 부상 시 자동으로 회복 주간을 선택하고, 사건과 시즌 종료에서는 멈춘다. 경기 리포트는 마지막 주 기준이며 진행 알림에 전체 출전 경기 수를 표시한다.
- 신규 선수는 숨겨진 재능을 한 번 추첨한다. 뛰어난 재능이면 모든 능력의 상한이 99가 된다. 성장량을 높여 좋은 훈련·회복 선택으로 전성기 전에 99를 달성할 수 있다. 기존 저장의 추첨 결과는 유지한다. 성장 상한·성장 배율·회복력 수치는 화면에 노출하지 않는다.
- 투수의 최종 목표는 사이영상이다. 게임 기준으로 MLB 완료 시즌 180이닝·200탈삼진·ERA 2.80 이하 또는 60이닝·40세이브·ERA 2.00 이하이면 수상한다. 여러 선수가 경쟁하는 실제 투표는 재현하지 않는다.
- 타자의 최종 목표는 미국 명예의 전당이다. MLB 10시즌을 완료하고 MLB 통산 3,000안타 또는 500홈런을 달성하면 은퇴 때 입성한다. 실제 명전 투표·대기 기간은 생략한다. 고교·KBO·NPB 기록은 입성 기준에 합산하지 않는다.
- 테스트: `node --test tests/pace-goals.test.cjs` (빠른 진행 정합성, 사건·시즌 경계, 수상·입성 조건, 타자·투수 전 능력 99 도달 검증).

## MLB 포스팅·FA 재수 업데이트

- 시즌 종료 후 포스팅 조건을 확인하고, 관심 MLB 구단과 1~4년 계약을 선택할 수 있다. KBO는 완료 7시즌, NPB는 완료 6시즌 및 다음 시즌 25세 이상을 게임 경력 기준으로 사용한다. 잔여 다년 계약이 없고 해외 FA 전이어야 한다.
- 구단 승인·스카우팅은 감독 신뢰 65, 종합 능력 75와 시즌 성적으로 판정한다. 타자는 350타석·OPS .800·(140안타 또는 20홈런), 투수는 120이닝·ERA 3.50·120K 또는 45이닝·ERA 3.20·50K·20세이브+홀드를 기준으로 한다. ERA는 이하, 그 외 수치는 이상이다. 이 기준은 게임 규칙이다.
- 제안을 수락하면 MLB로 이적하며 통산 기록과 리그별 서비스가 보존된다. 거절하면 기존 소속에서 다음 시즌을 진행할 수 있다. 제안 조회·저장 재접속으로 재추첨되지 않는다.
- FA 재수는 현재 팀과 1년 계약하고 FA 행사 이력을 소비하지 않는 선택이다. 다음 시즌 종료 후 다시 협상하며, 현재 시즌 성적이 계약 연봉에 반영되므로 제안이 오르거나 낮아진다. 다년 계약 기간에는 보수가 고정된다.
- 포스팅 협상 날짜·마이너 계약·이적료 정산·국적별 예외는 생략했다. NPB 경력 기준·성적 기준·자동 구단 승인과 MLB 이적 후 계약 만료 시 국제 FA 취급은 게임 간소화다.

## 경기 규칙·선택지·이벤트 확장 (2026-10-29)

- KBO 정규시즌은 연장 11회, NPB는 12회 후 동점이면 무승부다. MLB는 연장에 자동 주자 효과를 적용해 승패를 정한다. 팀 득점을 회별로 계산하는 간소화이며 개인 추가 타석·이닝은 합산하지 않는다.
- 야수의 수비 능력은 호수비에 의한 1실점 방지 확률에 반영한다. DH는 이 효과를 받지 않는다. 호수비·끝내기·승부치기·연장 무승부를 경기 리포트에서 확인할 수 있다.
- 이벤트는 시즌 3회에서 7회로 늘린다. 기존 3개 사건의 선택지는 보존하고, 추가 10종 중 4종이 선수·시즌에 따라 순환한다. 추가 사건은 각각 3개 선택지를 제공한다. 조회와 저장 복원으로 사건이 재추첨되지 않는다.
- 추가 사건: 영상 분석, 슬럼프, 스카우트, 트레이너 경고, 베테랑 멘토, 중요한 경기, 팬 응원, 주전 경쟁, 전문 캠프, 라이벌. 성장·피로·사기·신뢰·성장 보조·부상 예방을 선택한다.
- 훈련은 역할당 5개에서 7개로 늘린다. 타자: 타석 영상 분석·베이스 러닝. 투수: 타자 영상 분석·위기관리. 새로운 저장 필드 없이 기존 저장을 이어간다.

규칙의 출처와 간소화 범위는 [경기 규칙 적용 문서](BASEBALL_RULES.md)에 기록했다.

## 연봉 지갑과 라이프 상점 (2026-10-30)

- 성장·회복·보호 아이템은 기존 포인트(P)로 구매·사용한다. 연봉과 포인트는 서로 전환하지 않는다.
- 라이프 메뉴에서 실제 수령한 연봉으로 훈련용품·사치품·집과 공간을 구매한다. 가격은 만 원 단위의 게임 값이다. 계약 총액을 미리 쓸 수 없고, 매주 지급된 연봉만 사용할 수 있다.
- 18개 물품 중 분류별 최대 2개씩 매주 무작위 진열한다. 진열은 선수·시즌·주차에 고정되어 새로고침으로 재추첨되지 않는다. 구매한 물품은 다시 사지 않으며, 아직 보유하지 않은 다음 물품이 진열된다.
- 물품별 보이지 않는 차이는 선수 생성 정보와 물품에 따라 정해지고 저장된다. 구입 알림·설명·보유 목록·상점 조회 결과에는 효과 수치를 표시하지 않는다. 보유한 물품은 이후 주간 진행에 적용되며 여러 구매의 효과는 제한된 범위에서만 누적된다.
- 기존 v1/v2/v3 저장은 보유 물품이 없는 상태로 이어가고, 기존 누적 수령 연봉과 포인트를 보존한다. 사용 가능한 돈은 누적 수령액의 정수 부분에서 구매 지출을 뺀 값이다. 물품과 지출은 계약 변경·이적·시즌 전환에도 유지한다.
- 환매·대출·집값 변동·유지비는 이번 범위에 포함하지 않는다. 실제 결제는 없다. 저장 파일에는 게임 진행에 필요한 물품 정보가 들어가지만 플레이 화면에서는 효과 수치를 숨긴다.
- 화면은 목표·주간 일정·포인트 아이템을 접을 수 있도록 정리하고, 미선택 훈련의 긴 설명과 선수 유니폼 장식을 줄였다. 가격·잔액·선택한 훈련의 설명은 유지한다.
